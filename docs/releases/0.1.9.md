# OmO Web 0.1.9

## What's new

- **Data directory conflicts say exactly what's wrong.** Starting a second `omo-web serve` on the same data directory no longer crashes with a raw SQLite stack. The error now names the data directory, the occupying PID (kept in `omo-web.pid`), and the fix: stop the running instance or point `OMO_WEB_DATA` at another directory.
- **Startup errors print once, clearly.** Startup failures are reported as a single message instead of a Bun stack trace. The friendly hints extend to the documented troubleshooting entry as well.

## 更新内容

- **数据目录冲突说清原因。** 在同一数据目录再启动一次 `omo-web serve`，不再抛原始 SQLite 堆栈。错误会点名数据目录和占用进程的 PID（保存在 `omo-web.pid`），并给出处置：停止已运行的实例，或用 `OMO_WEB_DATA` 指向别的目录。
- **启动错误只打印一条、且清楚。** 启动期失败改为单行提示，不再甩 Bun 堆栈；排查文档同步了这条说明。

## Install or upgrade / 安装或升级

Once [npm lists `0.1.9`](https://www.npmjs.com/package/omo-web/v/0.1.9), install it directly. / [npm 上线 `0.1.9`](https://www.npmjs.com/package/omo-web/v/0.1.9) 后，可直接安装：

```sh
npm install -g omo-web@0.1.9
omo-web --version
```

Or download `omo-web-0.1.9.tgz` and its `.sha256` from **Assets**, then verify and install locally. / 也可以从 **Assets** 下载这两个文件，校验后在本地安装：

```sh
sha256sum -c omo-web-0.1.9.tgz.sha256 &&
  npm install -g ./omo-web-0.1.9.tgz &&
  omo-web --version
```

Keep `OMO_WEB_DATA` and your OmO profile when upgrading. The npm launcher needs Node.js 18+; the Web service needs Bun and OmO Native. The separate `.tar.gz` runs with Bun without npm. / 升级时保留 `OMO_WEB_DATA` 和 OmO profile。npm 启动器需要 Node.js 18+；Web 服务需要 Bun 和 OmO Native。独立 `.tar.gz` 不需要 npm 启动器。

## Verification / 验证范围

Conflict-start regressions cover a live holder and a fresh data directory (pidfile written, removed on close). A full restart of the local service verified the running instance starts with the new build and serves `200` on both the root page and `/api/bootstrap`. / 冲突启动回归覆盖了存活持有者和新数据目录（pidfile 写入、关闭时删除）。本地服务完整重启验证，新构建实例可正常启动，根页面与 `/api/bootstrap` 均返回 `200`。
