# OmO Web 0.1.7

**Fix: Continue in Web could reject a CLI session whose workspace was still authorized.** If the filesystem reported a different device number for the same directory, as observed on Btrfs, an old Web bookmark could block resume with “workspace not authorized or unavailable.” After upgrading, open **CLI History** and select **Continue in Web** again. Web checks the current workspace and the original CLI journal before opening it. It can create a fresh bookmark without rewriting the stale one or copying the conversation. A workspace that is no longer authorized is still refused.

**修复：「在 Web 继续」误拒仍获授权的 CLI 会话。** Btrfs 上同一个目录的设备号变化后，旧 Web 书签可能挡住续聊，提示「此工作目录未获授权或已不可用」。升级后，从「CLI 历史」重新点「在 Web 继续」。Web 会校验当前工作目录和原始 CLI 日志，必要时建立一个有效的新书签，不改写旧书签，也不复制对话。未获授权的目录仍会被拒绝。

## Install or upgrade / 安装或升级

Once [`0.1.7` is available on npm](https://www.npmjs.com/package/omo-web/v/0.1.7), install it directly. / [npm 上线 `0.1.7`](https://www.npmjs.com/package/omo-web/v/0.1.7) 后，可直接安装：

```sh
npm install -g omo-web@0.1.7
omo-web --version
```

With repository access, download `omo-web-0.1.7.tgz` and its `.sha256` from **Assets**, then verify and install them locally. / 有仓库访问权限时，可以从 **Assets** 下载这两个文件，校验后在本地安装：

```sh
sha256sum -c omo-web-0.1.7.tgz.sha256 &&
  npm install -g ./omo-web-0.1.7.tgz &&
  omo-web --version
```

Keep `OMO_WEB_DATA` and the OmO profile when upgrading. The npm launcher needs Node.js 18+; the Web service needs Bun and OmO Native. The separate `.tar.gz` runs with Bun without npm. / 升级时保留 `OMO_WEB_DATA` 和 OmO profile。npm 启动器需要 Node.js 18+；Web 服务需要 Bun 和 OmO Native。独立 `.tar.gz` 不需要 npm 启动器。

## Verification / 验证范围

The regression changes only the device-number field of a saved bookmark. It exercises the real Web resume endpoint, including concurrent requests, checks that the original is unchanged, and confirms that a replacement directory does not reactivate old Web sessions. / 回归测试只改变旧书签保存的设备号，验证实际续聊接口、并发去重和原始日志不变，也确认同名替换目录不能让旧 Web 会话重新获准。
